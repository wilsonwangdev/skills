# 行为验证

本目录按技能维护可复用案例：代表性请求、必要输入及可观察的判断标准。任务本身需要的日期、数量和合成数据可以保留；某次运行时间、成绩与应用测试统计属于运行证据。

## 案例目录

- [learn-from-agent-conversations](learn-from-agent-conversations.md)：概念追问、纠正原回答、缺少前文、直接解释与非学习请求。
- [build-maintainable-app](build-maintainable-app.md)：工程基线、模块职责、多语言与主题、提交检查、移动使用、导航与取消行为、元信息及任务范围。

## 执行与评审

执行者使用干净上下文，只接收待测技能、原始请求和必要输入；观察标准、旧输出和历史结论由评审者读取。评审检查实际决策与产物，不机械匹配固定措辞。需要判断技能是否带来改善时，以同一题目对比旧版或不使用技能的结果。

静态检查、受控试用、客户端加载和真人反馈分别报告；应用测试通过仅是对应应用的验收证据，不能充当技能通过率。

## 证据归属

- **技能试用**：实际输出、评分和日志留在独立运行目录，本仓库内可使用被忽略的 `.eval-workspace/`。提交评审或 CI 摘要记录日期、受测技能提交或快照、案例、模型与环境、证据位置和未覆盖项；未记录的信息如实说明。
- **验证范围**：技能验证使用自包含的试用材料和产物。真实项目的测试计数、构建日志和设备验证由该项目维护；经验先抽象成合成案例，不用跨仓验收记录补齐题面或解释技能结果。
- **案例改进**：从实际偏差提炼可复用输入和判据后更新案例，不追加运行纪要。需要长期保留的公开报告按明确范围单独审查，不逐次追加成日志。

试用使用合成材料或可公开输入；外部操作沿用当前任务授权。公开前检查身份信息、私有上下文和凭据。
