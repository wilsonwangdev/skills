# 行为验证案例

按 [行为验证约定](README.md) 选取题面交给执行者，观察标准供评审使用。案例不规定固定措辞，也不预先标成通过。

涉及操作的案例使用隔离临时目录与合成数据，不使用真实账户、私有业务材料或已安装的全局技能。源码可以本地创建，外部仓库、部署、推送与发布仍需当前任务授权。

## 从空目录创建独立应用

请求：

> 做一个可长期维护的阅读笔记 Web 应用。需要条目列表、编辑、搜索和本地保存，适合手机和桌面。我倾向 pnpm、Vite 和 Oxc 工具，先只在本地完成。

观察：查询当前稳定版与兼容条件，从官方模板初始化；框架选择与交互复杂度相符，标准结构保留；版本、脚本和元信息有明确来源，依赖锁定；设计依据与组件状态连贯；实际运行 Node 和浏览器相关验证；没有自建开发服务器、测试框架或通用解析器，也没有因技能擅自部署。

## 入口职责与可复用的模块示例

原始材料：

> 一个已有 React 应用的入口同时实现导航外壳、首页、记录编辑页、共享草稿持久化和异步提交。页面内的展开状态只在该页面使用，草稿需要跨页面保留；离开提交页面后迟到结果不能覆盖新任务。已有浏览器测试覆盖这些行为，非首屏设置按需加载。

请求：

> 入口包含过多具体实现，请按可持续维护的方式组件化、模块化，让以后添加页面时能参考正确范式。保留现有行为，不升级依赖。

观察：沿调用链确定页面、业务流程和状态的职责，入口承担组合；共享草稿保持唯一所有者，局部状态靠近使用处，请求生命周期集中管理，接口表达业务操作。通过实际产物说明修改一个页面或业务规则时影响的位置，并验证既有导航、草稿、取消与按需加载。没有把全部实现搬进一个大 Hook、以大量 setter 或通用上下文暴露内部细节、按任意行数机械拆文件，也没有重建工具链。若交付模板，同样以真实最小流程示范职责分工，规约与源码一致。

## 把手写原型整理为工程

原始材料：

> 一个合成原型有静态入口、手写字符串渲染、自己的目录监听服务器、用普通 Node 脚本运行的断言、一个自制 DOM 对象和数据校验器。条目去重、排序规则已实现，并有示例数据。

请求：

> 保留功能，把原型整理成能继续迭代的 Web 项目，优先复用成熟方案。

观察：通过官方模板建立迁移基线，保留和验证业务规则；成熟方案替代基础设施，自定义代码留下具体业务缺口的适配；浏览器交互由正式工具在真实浏览器验证。没有仅改文件名或包脚本后声称完成迁移，也没有重新实现另一套基础设施。

观察：先读取现有约定，复用框架、设计组件与有用测试；按任务补充项目上下文入口和必要验证，没有为满足技能偏好重建成 Vite 项目、强制替换成熟测试或升级全部依赖。

## 多设备与复杂内容

请求：

观察：在多种真实视口与断点附近操作，检查页面和局部滚动、操作可达性、触摸目标、键盘焦点及相关状态；报告实际尺寸、操作结果与设备限制。没有把 CSS 中存在断点或截图成功等同于体验验收，也没有隐藏主要内容解决溢出。

观察：公开 Agent 入口、设计说明和按需项目技能采用通用约定；样例被合成数据替换，本地材料和密钥不进入前端资源；检查已跟踪源码及构建产物。没有只添加忽略规则就声称已清除公开内容，也没有把作者身份或本机目录写进共享技能。

## 未重复提醒时也采用工程基线

请求：

> 从空目录做一个可长期迭代的收藏夹 Web。先实现一个最小可用界面，其余功能以后添加。

观察：无需用户逐项重述，也选择当前稳定且兼容的 TypeScript 模板，覆盖第一方界面、服务及测试；严格类型、检查、格式和提交前检查先落实。代表性界面实际接通语言切换、亮色/暗色/系统模式及偏好恢复，而不是先硬编码全部业务再留待重构。

## 界面语言与内容分别维护

请求：

> 给记录工具增加界面语言切换。记录正文由用户填写，可能包含代码和引用；有日期、按钮、验证错误和空状态。

观察：使用成熟国际化机制及区域格式，按维护范围组织独立语言资源、集中注册并检查文案键完整性，覆盖错误和无障碍名称、页面语言、回退与保存；用户正文、代码和引用保持原意。切换后用长文案验证布局，不把一个语言下的成功截图称为整体通过，也不按词片段拼接句子。

## 多主题与定制有明确范围

请求：

> 第一版支持亮色、暗色、跟随系统，能记住我的选择；以后可能增加其他配色主题和用户定制，暂时不用做完整主题编辑器。

观察：外观模式与主题配置独立，复用统一设计变量和成熟机制；通过两个小型命名主题与一个允许覆盖项证明实际生效、保存、回退和恢复，正式设置入口及编辑器按范围保留。首屏、刷新、系统变化和显式选择可验证。扩展点与已实现功能分别说明，没有把一组颜色常量称为暗色支持，也没有擅自开发完整编辑器或主题市场。

## 真实提交检查与部分暂存

请求：

> 给一个新的 TypeScript 工程接通提交前质量检查，请实际验证。有人会只暂存文件中的部分改动。

观察：采用成熟钩子和暂存工具，从没有生成钩子或本机Git配置的新克隆按文档安装后自动启用；独立手动运行prepare不冒充安装链验收，项目命令能直接找到暂存检查；类型检查使用项目配置而非追加文件名。隔离仓库中有效提交通过，真实类型与静态检查违规失败且 HEAD 不动；暂存版本有类型错误而未暂存修改已修好时仍失败，格式被修正或阻断，未暂存内容未丢失或误提交。说明暂存内容与工作树检查的范围；CI 检查最终提交，不把跳过钩子当作验收成功。

## 独立应用的首页与回访路径

请求：
