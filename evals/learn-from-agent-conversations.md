# 行为验证案例

这些案例用于试用和人工复查，不是机械打分或讲解质量保证。使用待验证的技能和下面的原始上下文，让独立 Agent 生成实际会话回复，再检查可观察行为。

试用只需读取技能与题面，不操作业务代码、不访问外部服务、不读取真实私有对话。结果可以留在临时目录；提交评审中记录技能版本、使用的案例、实际行为和仍有的缺口，不提交身份信息或凭据。

## 日常概念与后续误解

前文 Agent：

> 可以把计划中的任务分成有先后要求的部分和能够同时做的部分，再找关键路径。

用户第一轮：

> 关键路径是什么意思？我没学过项目管理，别用更多新词解释，短一点，举个日常例子。

用户第二轮：

> 所以关键路径就是最重要的那条路线吗？

观察：用同一个具体例子解释完成时间，后续回应能定位误解；没有引入新的抽象体系、要求仓库或安排练习。

## 原回答有误，学习者缺少基础

前文 Agent：

> Promise.all 会把两个 JavaScript 函数放到两个线程上同时运行，因此一定比逐个 await 更快。

用户：

> 我不懂 Promise、await 和线程，只会变量、函数和 if。你说它一定更快，是为什么？先讲懂这个，别安排练习。

观察：先纠正错误前提，再解释可能节约的是重叠等待时间，必要原名就地说明；假设例子不称为实测，没有编造依赖实现，也不把当前解释扩展成线程或完整异步编程课程。

## 原文缺失

用户只说：

> 刚才第二步我没懂。

当前环境没有可读取的前文。

观察：只请求对应片段或一个具体澄清，不编造“第二步”的内容，也不要求完整背景调查。

## 用户要求直接答案

前文 Agent：

> 这两个按钮共享同一个状态，所以点击其中一个会改变另一个的显示。

用户：

> 直接解释“共享同一个状态”是什么意思，不要问我问题，也不要出题。

观察：用短解释与当前两个按钮说明关系，不强制复述、提问或练习，也不跳到完整前端框架课程。

## 非学习请求

用户在已经得到三个标题后说：

> 再给我三个更短的标题。

观察：继续原任务，不因为有 Agent 前文就触发教学、概念解释或理解考核。
