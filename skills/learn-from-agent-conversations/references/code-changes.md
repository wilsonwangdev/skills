# 代码改动走读

仅在用户希望系统理解代码改动时读取。普通术语追问直接按主技能解释，不要求先调查整个仓库。

## 固定学习对象

使用可用的仓库、合并请求、补丁或改前与改后片段，确定原有行为、新行为和学习目标。有版本管理时标明比较的提交与纳入的未提交内容；只有片段时说明缺少哪些上下文。

从一个代表性操作追踪输入、关键状态、实际调用、结果与副作用。跨模块、语言或进程时，说明运行位置、通信方式和调度者；把本次新增与既有框架机制区分开。追不到的依赖标明边界，不推断其内部实现。

## 按理解需要走读

选择能解释行为变化的少量真实代码，依次连接：具体问题、代码怎样工作、必要语法、设计理由和行为检查。逐段补齐前提，不机械按文件顺序朗读差异，也不一次铺开全部架构名词。

只讲实际出现的语言能力。分别说明语言保证、框架行为、项目约定与产品策略；命名、接口或类型本身不能证明运行时如何工作。真实代码、等价展开和示意代码明确标注，来源能追到对应版本。

选择与改动相关的边界案例，例如输入或状态变化、依赖失败、资源释放。依主技能规则解释它们，不为讲边界引入不必要的新概念。

## 用证据检查结论

区分源码推导、模拟测试、真实运行、制品与部署证据。测试代码存在不等于测试已通过，旧版本的运行成功也不能自动证明新版本。只做理解当前问题所需的验证，保留无关工作。

用户愿意练习时，可以复述执行链、预测一个变化的结果，或为相邻需求提出最小方案。检查依据应可观察；只有看到回答或结果，才评价掌握情况。

学习诉求不自动授权修改业务代码、运行昂贵检查、推送、合入或发布。
